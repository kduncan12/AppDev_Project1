# CMPS 3390 — Project 1

Two desktop GUI apps built with **Python and Qt (PySide6)** for CMPS 3390 Application Development at CSU Bakersfield, Fall 2026.

Written on Kubuntu Linux, presented on macOS — the same source runs on both.

---

## The apps

### App 1 — Hello

A two-view app in a single window.

- The first view has one button labelled **Hello**.
- Clicking it switches to a second view with a **Hello World** label and an **OK** button.
- **OK** returns to the first view.

### App 2 — Habit Tracker

A one-view habit log.

- A table labelled **Habit List** with two columns: **Habit** and **Date**.
- A **Habit:** label, a text field, and an **Add** button.
- **Add** stamps the current date and time, appends the habit as a new row, and clears the field. Pressing **Enter** in the field does the same.
- Blank input is ignored.

## Setup

**macOS or Linux, using a virtual environment:**

```bash
git clone <https://github.com/kduncan12/AppDev_Project1>
cd AppDev_Project1
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**Kubuntu / Ubuntu, using the system package instead:**

```bash
sudo apt install python3-pyside6.qtwidgets
```

The PySide6 install is platform-specific. Only the `.py` files move between machines — never copy a `.venv` folder from one computer to another.

### Check the environment

```bash
python3 qtcheck.py
```

It prints the interpreter, PySide6 and Qt versions, and the platform plugin, then opens a small window. If the window appears, everything is working. A successful `import PySide6` alone does not prove the GUI layer works; this does.

## Design notes

**Two views, one window.** App 1 uses a `QStackedWidget`, which holds both pages and shows one at a time. Both pages are built once at startup; switching is a single `setCurrentIndex` call. A second window or a modal dialog would also have worked, but the stack keeps one window and makes "go back" a one-line change.

**Signals and slots.** Each button's `clicked` signal is connected to a method (the slot) that does the work — Qt's event system, and the equivalent of the "listener" the spec describes. In App 2 the same `add_habit` slot is connected to both the Add button and the text field's `returnPressed` signal, so Enter and the button behave identically.



**Read-only cells.** The table's edit triggers are disabled. The spec is add-only, and the timestamps are generated by the app, so they shouldn't be editable.

**Why PySide6.** Qt is on the course's Desktop UI framework list, and Python is the language I am more familiar with, so the only new material was Qt's widgets. PySide6 is the official Qt binding and is LGPL; PyQt6 is GPL. Either is fine for coursework, but PySide6 doesn't constrain future projects so I'd rather build habits in PySide6.
